STV & margins

Single Transferable Vote (STV)

  • Multi-winner system with ranked ballots
  • Aims for proportional representation
  • A.k.a. “proportional ranked-choice voting”

Used for national and other government elections

  • Australia, Ireland, Malta

Used for local government elections

  • Aotearoa/New Zealand, Northern Ireland, Scotland, USA

STV voting

Voters rank candidates in preference order

Examples

  • (1) Melanie, (2) Peter, (3) David
  • (1) Peter, (2) Melanie, (3) David
  • (1) David

Compact representation

  • [Melanie, Peter, David]
  • [Peter, Melanie, David]
  • [David]

STV counting (key concepts)

  • Quota (Droop quota):

Q = \left\lfloor \frac{\text{\# ballots}}{\text{\# seats} + 1} \right\rfloor + 1

  • Seating: Candidates reaching Q votes are elected

    • Distribute surplus votes at reduced transfer value:

\tau = \frac{\text{\# tally} - Q}{\text{\# tally}}

  • Elimination: If no candidate reaches Q, eliminate lowest candidate

    • Distribute ballots at full value.

How close is the election?

Margin of victory

The minimum number of cast ballots that must be altered to change the set of elected winners W.


Also referred to as the ‘margin’

Motivation: Margin \rightarrow Auditing

Risk-limiting audits (RLAs)

  • Statistical confidence in election outcomes

  • No universally efficient RLA method for all STV elections

  • Mismatch-based RLAs (Ek et al. 2026) will work

  • Require a lower bound: lb \leqslant \text{margin}

Margin bounding

  • Loose lower bounds \Rightarrow inefficient RLAs

  • Need tight lower bounds!

Why is calculating STV margins hard?

  1. Elimination cascades

    • Small early changes can trigger large changes later.

  2. Non-monotonicity

    • Adding votes to E can cause E’s preferred ally to lose.

  3. Non-linearity

    • \tau depends non-linearly on the vote tallies.

Margin calculation algorithms

Existing method (BST-19)

  • Election order prefix (\pi):

    • E.g., \pi = (C^+, E^+, A^-)

  • Prefix tree:

    • Root: empty sequence ()

    • Branching: seat candidate c^+ or eliminate candidate c^-

  • Best-first branch-and-bound:

    • Maintain frontier F of nodes (lb, \pi), sorted by lower bound lb

      • Calculate lb using lower-bounding heuristics

    • Track running upper limit rul (cheapest known outcome-changing manipulation)

      • Initialise rul with an upper bound
      • Update rul using complete outcomes \pi (fully expanded branches)

    • Prunes nodes where lb \geqslant rul

    • Return smallest lb (same as rul once all nodes pruned)

Lower-bounding heuristics

Elimination lower bound

  • l_{\text{elim}}(\pi, c) = Given \pi, minimum cost to keep eliminated candidate c lowest, in the round when they should be eliminated

Quota lower bound

  • l_{\text{quota}}(\pi, c) = Given \pi, minimum cost to raise seated candidate c to quota Q, in the round they should be seated

MINLP

  • Mixed-integer non-linear program (MINLP), with linear relaxations
  • Computes minimal manipulations given \pi

New advances (STV-26)

  • Upper bounds: Use ConcreteSTV heuristic for tighter initial rul

  • Exact MINLPs: Replaced linear relaxations with exact non-linear programs, and use super-candidate relaxation

  • Context-aware tally bounds: Rigorous tracking of ballot piles (B^{\text{must}}, B^{\text{maybe}}) and transfer value ranges (T^{\min}, T^{\max})

  • New lower bounds: Introduced Displacement Lower Bound (l_{\text{disp}}) to anticipate forced winner changes in future rounds

  • Pruning: Dominance Pruning to detect and prune structurally equivalent search paths

STV-26 introduces five key improvements over the BST-19 baseline. We integrate tight upper bounds, solve exact MINLPs with super-candidate relaxation, track context-aware ballot piles, introduce a new displacement lower bound l_disp, and apply dominance pruning. Let’s look at each of these components in detail.

1. Upper bounds with ConcreteSTV

  • Role of the Running Upper Limit (rul):

    • Defines global threshold for search tree pruning.

    • Any partial prefix requiring \ge rul edits is immediately discarded.

  • ConcreteSTV Integration:

    • Performs local heuristic search for explicit, valid ballot modifications that alter winner set W' \neq W.

    • Provides near-optimal initial upper bounds.

  • Impact on Search:

    • A tighter initial rul prunes vast subtrees at shallow depths before running expensive optimization solver calls.

Component 1 addresses the starting upper limit. BST-19 used loose initial upper bounds, which meant the algorithm spent hours expanding unviable subtrees before tightening the limit. By integrating ConcreteSTV, which searches for explicit ballot modifications, we start with a tight running limit right at the root.

ConcreteSTV: https://github.com/AndrewConway/ConcreteSTV

2. Exact MINLP solving & super-candidate relaxation

  • Moving Beyond Linear Relaxations:

    • BST-19 linearized STV transfer rules, introducing loose bounds.

    • STV-26 solves exact Mixed-Integer Non-Linear Programs (MINLPs) preserving true WIGM rules.

  • Super-Candidate Relaxation (\tilde{\pi}):

    • Groups sequences of 3+ eliminated candidates into a single super candidate (e.g., (B, E, F) \rightarrow BE).

    • Leaves the final candidate c_n unmerged to prevent over-relaxation:

      \text{Original: } [(A, 0), (C, 1), (B, 0), (E, 0), (F, 0), (D, 1)]

      \text{Relaxed } \tilde{\pi}: [(A, 0), (C, 1), (\mathbf{BE}, 0), (F, 0), (D, 1)]

  • Benefit: Reduces optimization variables dramatically while maintaining exact non-linear transfer semantics.

To make exact MINLP solving computationally tractable over long elimination sequences, we introduce Super-Candidate Relaxation. We merge internal sequences of eliminated candidates into a single super-candidate, leaving the last candidate separate. This drastically reduces the number of variables in the solver while preserving exact non-linear WIGM transfer value equations.

3. Context-aware tally bounds

  • Tracking Ballot Movements:

    • B^{\text{must}}_{\pi, c, r}: Ballots that definitely reside in candidate c’s pile at round r.

    • B^{\text{maybe}}_{\pi, c, r}: Ballots that could possibly reside in candidate c’s pile at round r.

  • Transfer Value Ranges:

    T^{\min}_{\pi, c, r} = \frac{\max(Q, V^{\min}) - Q}{\max(Q, V^{\min})}, \quad T^{\max}_{\pi, c, r} = \frac{\max(Q, V^{\max}) - Q}{\max(Q, V^{\max})}

  • Example (from Running Example):

    • Candidate D at Round 3 under \pi = [(C, 1), (E, 1), (A, 0)]:

    • V^{\min}_{\pi, D, 3} = 163.63 votes vs. V^{\max}_{\pi, D, 3} = 201.96 votes.

    • Previous BST-19 bounds coarsely assumed ballot values of 0 or 1!

When multiple seatings occur in sequence, exact ballot locations depend on candidate quota timing. STV-26 tracks B_must and B_maybe sets along with upper and lower bounds on transfer values T_min and T_max. In our running example, candidate D’s tally is bounded tightly between 163.63 and 201.96, whereas BST-19 coarsely assumed ballot values between 0 and 1.

4. Lower bounds

  • Elimination Lower Bound (l_{\text{elim}}): Min cost to keep eliminated candidate lowest.

    l_{\text{elim}}(\pi, c) = \max_{c' \in S_{\pi, r} \setminus \{c\}} \left( \frac{V^{\min}_{\pi, c, r} - V^{\max}_{\pi, c', r}}{2} \right)^+

  • Quota Lower Bound (l_{\text{quota}}): Min cost to raise seated candidate to quota Q.

    l_{\text{quota}}(\pi, c) = (Q - V^{\max}_{\pi, c, r})^+

  • Displacement Lower Bound (l_{\text{disp}}) — NEW:

    • Evaluates future rounds beyond prefix \pi.

    • Forces at least one reported loser c \in L_\pi to displace a reported winner w \in W:

      l_{\text{disp}}(\pi) = \min_{c \in L_\pi} \max \left\{ \text{DispCost}_{\pi, c}, \min(\text{QuotaCost}_{\pi, c}, \text{LeftAtEndCost}_{\pi, c}) \right\}

For every node in the search tree, we compute elimination, quota, and displacement lower bounds. The key addition in STV-26 is l_disp. Even if a prefix matches early reported rounds with 0 cost, l_disp looks ahead to future rounds to determine the minimum edits needed for a standing loser to displace a standing winner later in tabulation.

5. Dominance pruning

  • Core Observation:

    • Multiple distinct search paths lead to identical super-candidate relaxed states (\tilde{\pi} \equiv \tilde{\pi}').

  • Dominance Rule:

    • Node (l, \pi) is dominated by node (l', \pi') if \tilde{\pi} \equiv \tilde{\pi}' and l' \le l.

    • If an equivalent path with a smaller or equal bound has already been explored or exists in frontier F, discard (l, \pi) immediately.

  • Why It Works:

    • Future MINLPs built on top of \pi and \pi' are identical.

    • Eliminates duplicate subtree expansions before calling expensive MINLP solvers.

Dominance pruning is a major speedup factor in STV-26. Different permutation paths often resolve to the exact same relaxed super-candidate structure pi-tilde. If we have already evaluated a path with the same relaxed structure and a lower bound, any future extension will yield an identical MINLP optimization problem. We can safely discard the higher-cost duplicate node immediately.

Results

BST-19 re-implemented

Understanding the difference between the published baseline and our re-implementation:

BST-19 (Blom et al., 2019)

  • Ruleset: Australian Senate rules (fractional surplus handling differs on subsequent transfers).
  • Environment: Original 2019 codebase and hardware.
  • Timeout: 12 hours (43,200s).
  • Pruning & MINLP: Linearized MINLP relaxation; older lower-bounding heuristics.

BST-19* (Re-implementation)

  • Ruleset: Weighted Inclusive Gregory Method (WIGM). Equivalent to Senate rules for 2-seat contests.
  • Environment: Modern 32 vCPU, 128 GB RAM server with 30-node parallelization.
  • Timeout: 10,000s.
  • Purpose: Isolates hardware/solver gains vs. new algorithmic contributions in STV-26.

Why distinguish BST-19 from BST-19? BST-19 uses the exact same algorithmic principles as BST-19, but runs on modern hardware with parallelization and aligned WIGM rules. Comparing BST-19* to STV-26 allows us to isolate the pure benefit of our new algorithmic contributions (direct MINLP solving, displacement bounds, dominance pruning) from raw compute power improvements.

Summary

  • Contributions:

    • Exact MINLP solving with super-candidate relaxation.

    • Context-aware tally bounds (B^{\text{must}}, B^{\text{maybe}}) and displacement bound l_{\text{disp}}.

    • Dominance pruning to eliminate redundant search branches.

    • Proven exact margins internationally and up to 20x higher bounds in Australia.

  • Open-source implementation: https://github.com/michelleblom/pymarginstv

Future directions

  • Scaling to large 6–12 seat Australian Senate elections (100+ candidates).

  • Extending bounds to alternative STV variants (e.g., Meek’s method).
